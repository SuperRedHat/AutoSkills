# 长跑驱动：`autoskills.mjs run`

让项目里的任务一个接一个做下去，你不用守着。每个任务开一个全新的无头会话（`claude -p`）去做；会话结束后，驱动在提交好的代码上把任务的验证命令再跑一遍；到了停点就停，留一份报告。

驱动**只读账本，不写账本，不改任务状态，也不替你验收**。待验收的任务一直等你本人的话。

## 怎么敲

在普通的 PowerShell 窗口里敲，不要在 Claude Code 会话里敲：

```powershell
node <AutoSkills 仓库>\scripts\autoskills.mjs run <项目目录>
```

项目目录要是 git 仓库的根目录，里面有账本（`.claude\state\tasks.json`）。命令是仓库里的脚本，不用部署。

常用的写法：

```powershell
# 睡前开跑，早上 7 点以后不再开新任务
node <仓库>\scripts\autoskills.mjs run <项目目录> --until 07:00

# 先试两个任务
node <仓库>\scripts\autoskills.mjs run <项目目录> --max-tasks 2 --model claude-opus-5-5 --effort high
```

## 选项

| 选项 | 作用 | 默认 |
|---|---|---|
| `--model <模型>` | 原样传给每个会话 | 不传（用你设置里的模型） |
| `--effort <档位>` | 原样传给每个会话 | 不传 |
| `--permission-mode <模式>` | 会话的权限模式，可选 acceptEdits、auto、bypassPermissions、manual、dontAsk、plan | auto（自动模式） |
| `--tasks-per-session <N>` | 一个会话最多做几个任务 | 1 |
| `--until <HH:MM>` | 本地时间，过了这个点不再开新任务；已经过了今天的这个点就算明天的 | 关 |
| `--max-tasks <N>` | 做完（完成或待验收）N 个任务后不再开新任务 | 关 |
| `--verify-timeout-min <分钟>` | 复验时一条验证命令最多跑多久，超时就结束它，算没过 | 30 |
| `--idle-min <分钟>` | 会话这么久没有任何输出就结束它（连同它起的进程），下一个会话接着做 | 30 |
| `--cli <文件>` | claude 可执行文件 | 环境变量 `CLAUDE_EXE`，没有就用 PATH 上的 claude |
| `--help` | 打印用法 | — |

权限模式默认用自动模式，是在测试仓库里探过的：自动模式下无头会话能把一个任务做完；被守卫钩子或拒绝规则拦下的命令，会话照常收场，不会卡住等人点。探查记录在 `docs/windows/finish/a-probes.md`。

## 一轮怎么走

1. 读账本，挑任务：
   - 先挑“进行中”的；备注里写着“受阻：”的跳过。
   - 没有进行中的，就按账本服务端同样的规则挑下一个就绪任务（优先级高的先，同优先级按建的顺序）。
   - 一个能做的都没有，就不起会话、停下，写明原因：全部做完；只剩等你验收或决定的；剩下的都受阻。
2. 起会话，提示词是“用 project-next 只做 <任务号>；做完、验证、提交、记账就结束；这是无人值守的运行，不要提问，要我定的事写进任务备注和汇报”。
3. 会话结束后，看账本日志和 git：任务状态变没变，有没有新提交。
4. 任务到了“完成”或“待验收”，驱动复验：
   - 工作目录要干净：`git status` 里没有东西才算，账本目录（`.claude\state\`）和 `.autoskills\` 下的不算。
   - 把任务的验证命令逐条重跑，每条一个进程，在项目根目录跑，输出存进这次运行的目录。
5. 复验没过：
   - 任务已经是“完成”：下一个会话由驱动点名，让它照 project-plan 的做法新建一个返工任务（依赖为空、优先级最高、验证命令和原任务一样）并只做它。修两轮还不过，驱动让会话在返工任务的备注里写“受阻：…”，之后跳过它。返工收尾之前，别的任务不抢在前面。
   - 任务在“待验收”：不动它，报告里标出“复验没过，建议驳回”。驳不驳回由你定。

## 刹车

任何限额都只管还开不开下一个任务，不打断正在做的任务。做完的任务已经提交、记账，停下不丢东西。

| 管什么 | 做法 | 默认 |
|---|---|---|
| token | 不设上限。每做完一个任务打印已用多少，按当前平均推算剩下的还要多少 | — |
| 时间 | `--until HH:MM` | 关 |
| 任务数 | `--max-tasks N` | 关 |
| 没进展 | 连续 3 个会话既没有新提交、任务状态也没变，就停 | 开 |
| 同一个任务反复不过 | 返工两轮还不过，标受阻、跳过 | 开 |
| 会话挂死 | 30 分钟没有任何输出才结束这个会话；改了一半的留在工作目录里，下一个会话接着做 | 开 |
| 订阅额度用完 | 等 10、20、40 分钟，之后每次 60 分钟，再接着做同一个任务；不算失败，等待记进报告 | 开 |

额度用完是照会话输出里的文字认的（和评测驱动同一条规则）。真遇到的时候，报告里每次等待都有一行。

## 怎么停

- **稳妥的停法**：另开一个窗口敲

  ```powershell
  node <仓库>\scripts\autoskills.mjs stop <项目目录>
  ```

  它在项目里放一个停止文件（`.autoskills\run.stop`），驱动做完当前任务后停，退出时删掉它。在等额度恢复的时候放，驱动不再等，直接停。没有驱动在跑时，`stop` 什么也不写，退出码 1。
- **Ctrl+C 按一次**：和停止文件一样，做完当前任务后停。会话在自己的（隐藏的）控制台里跑，收不到这次 Ctrl+C，所以当前任务不会被打断。
- **Ctrl+C 按两次**：立即停。当前会话连同它起的进程一起结束，改了一半的留在工作目录里，账本里那个任务多半还是“进行中”；下次开跑会先接着做它。

## 跑着的时候

- **不要在同一个项目里另开会话记账。** 账本没有锁，两个进程同时写可能丢更新。要看进度用 project-status（只读）或看报告。
- 一个项目同时只许一个驱动：启动时写锁文件 `.autoskills\run.lock`（进程号、运行名、开始时间），退出时删。已有活着的驱动，第二个拒绝启动；锁里的进程已经不在了（上次异常退出），就接手，报告里记一句。
- 验收：报告和验收包会列出等你验收的任务。验收照旧在会话里用你本人的话说（project-feedback）。验收之后别让驱动和你的会话同时在同一个项目里跑。

## 报告在哪

每次运行一个目录：`<项目>\.autoskills\runs\<运行名>\`，运行名是开始时间（UTC），比如 `2026-11-19T02-30-05Z`。

| 文件 | 内容 |
|---|---|
| `report.md` | 给你看的报告：每个任务一行（结果、提交号、复验结果、token、用时）；合计和估计；等你验收的；受阻的和原因；返工；等了几次额度；每个会话怎么结束；验收包出没出 |
| `run.json` | 驱动自己的记录：选项、每个会话（提示词、退出码、token、前后的 HEAD、新提交、状态变化）、复验、返工、等待 |
| `tasks\<任务号>.verify.json` | 一个任务的复验结果：`{task_id, commit, clean, passed, at, commands: [{command, exit_code, ms, log}]}`；没过或没跑时多一个 `reason`，工作目录不干净时多一个 `dirty` |
| `tasks\<任务号>.verify-<n>.log` | 第 n 条验证命令的输出 |
| `sessions\<序号>-<任务号>.stdout.jsonl`、`.stderr.log` | 会话的原始输出 |
| `accept.log` | 结束时出验收包的输出 |

结束时驱动顺手出一份验收包（`autoskills.mjs accept`）。验收包没出成，报告里记一行，不影响退出码。

退出码：0 停在正常的停点（全部做完、只剩你的事、停止文件或 Ctrl+C、到了 `--until` 或 `--max-tasks`）；1 被刹车停下（没进展、剩下的都受阻）或出错；2 用法错误。

## 项目设置

可选的 `<项目>\.autoskills\run.json`，两项都可以不写：

```json
{
  "verify_shell": "powershell",
  "awaiting_blocks_downstream": true
}
```

- `verify_shell`：复验用哪个 shell 跑验证命令。`powershell`（默认）是 `powershell.exe -NoProfile -NonInteractive -Command <命令>`，Windows PowerShell 5.1；`bash` 是 Git for Windows 的 bash.exe（`bash -c <命令>`），不用 WSL 的启动器。验证命令里有 `&&` 这类 PowerShell 5.1 不认的写法时用 `bash`。注意 PowerShell 下一条外部命令失败，退出码记成 1，不是那条命令自己的退出码。
- `awaiting_blocks_downstream`：项目契约写了“待验收不挡下游：是”时，这里写 `false`，驱动才会去做依赖待验收任务的下游任务，不会提前停。阶段门禁（stage_gate）照样挡。

写了不认识的值，驱动拒绝启动并说明哪一项不对。

## 已知的局限

- 复验在原地跑，只要求工作目录干净。被 git 忽略的文件（依赖、构建产物）还在，所以查得出“忘了提交”，查不出“靠本机才有的东西才过”。
- 每个任务新开会话，固定开销（技能、契约、账本工具的说明）每次都要付一遍。小任务上未必比一个长会话省。
- 返工那条路（会话按提示新建返工任务）只在替身测试里走过，真实会话里还没碰到过复验没过。
- 一个会话做多个任务（`--tasks-per-session` 大于 1）时，会话的 token 和用时记在它点名的第一个任务上。
