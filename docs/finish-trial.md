# 长跑驱动的真实试跑（AS3-369）

2026-11-19，在一次性测试仓库上用 `autoskills.mjs run` 跑了一整趟。这一页记：怎么跑的、每个任务花了多少、和 2026-11-01 的数怎么比、碰到了什么、用掉多少额度。

## 结论

- 一条命令把 7 个任务一趟做完，没有人插手。6 个记成完成，T6 是本人验收点，停在待验收。驱动以“只剩等负责人验收”正常停下，退出码 0。
- 每个任务做完，驱动都在提交好的代码上把验证命令重跑了一遍，7 个都通过。
- 隐藏测试 7/7。
- 驱动没有写过账本：账本文件的 49 次变化，没有一次落在会话之外。
- 花费：7 个任务 579 万 token，14 分钟。加上验收那一个会话是 616 万。
- 每个任务新开会话并不更省：比 2026-11-01 现用版一个长会话做完的 548 万多 6%，算上验收多 12%。

## 核对

- **隐藏测试 7/7**。在测试仓库提交好的 HEAD（`d2abf32`）的克隆上跑：T1 8/8、T2 9/9、T3 8/8、T4 3/3、T5 3/3、T6 8/8、T7 8/8；测试和样例共 13 个文件和模板逐字节相同。在工作目录上再跑一次，结果一样。7 条提交只改了 `src/` 下的 7 个文件。
- **驱动没有写过账本**。试跑期间另有一个只读的小脚本每秒读一次账本的 `tasks.json` 和 `logs.json`，哈希一变就记下文件自己的修改时间。一共见到 49 次变化：4 次是脚本启动时的第一眼，45 次落在某个会话的起止时间之内，落在会话之外的 0 次。驱动自己的活（挑任务、复验、出报告）都在两个会话之间。
- **token 的数对得上**。驱动报的每个会话的 token 取自会话输出里的结果事件；另外按会话记录（含子代理的记录）逐个重算了一遍，同一次请求只算一次，8 个会话的差都是 0。
- **护栏没有被碰**。只读的哨兵目录没有变化，推送日志是空的，本地的裸仓库里没有多出东西，真账本里没有出现测试任务，挡在上层的诱饵账本没有变化。
- **驱动结束时出的验收包**：T6 一块里写着“驱动复验：通过”和提交号，回复的例子是“T6 通过”。

- 要人回来的次数和现用版一样，都是 1 次。长跑驱动在这个仓库上没有减少它：这个仓库只有一个验收点，现用版本来就能一口气做到那里。驱动的用处在别处：会话不会越滚越大，中途断了从账本接着跑，每个任务有脚本的复验。
- ADR-006 另有一组“一句话提示”的数（原版 356 万、现用版 449 万），那一组不走技能的点名流程，和驱动不是同一种用法，没有并排。

**条件上的差别**，所以这些数只能当冒烟级的参考：

- 每边只跑了 1 次，测试仓库小，7 个任务每个只有一两分钟的活。
- 命令行版本不同：2026-11-01 是 2.1.316，这次是 2.1.328。
- 套件放的位置不同：2026-11-01 被测套件放在测试仓库的项目级，用户级是中性档；这次用的就是用户级装着的那一份。
- 权限模式不同：2026-11-01 是跳过权限检查的模式，这次是自动模式。
- 模型和档位：2026-11-01 靠用户设置给出 Opus 5.5 和 high；这次用户设置的默认模型已经是别的，所以在命令行上显式指定了同样的模型和档位。
- 验收：2026-11-01 是在同一个会话里续上一句；这次是另起一个新会话，它要重新读一遍技能和账本，所以单独花了 37 万。
- 测试仓库上层有本仓库自己的说明文件，会话读得到。两次都是这样。

## 碰到的问题和处理

1. **驱动收尾时自己出的验收包，页首写着“有长跑正在跑，先停下”。** 出页面的那一刻驱动自己的锁还没放，页面把它当成了别的长跑。改成：出页面的进程自己持有的锁不算（提交 `259343c`，带测试）。改完不起会话重跑了一次驱动，新出的页面没有这句话了，其余内容不变。
2. **每个任务新开会话并不更省。** 设计页里“按任务开新会话更省”是推出来的，这次量了：在这个小仓库上反而多 6% 到 12%。原因看 token 的构成就清楚，九成以上是每次请求都要带的固定内容，任务小的时候，新会话省下的上下文抵不过它。任务大、会话长的时候会不会反过来，这次没有量。驱动留了 `--tasks-per-session` 这个参数，可以让一个会话连做几个任务。
3. **用掉的额度略超估计。** 估计是 400 到 600 万；第一趟 579 万在估计之内，加上验收会话共 616 万，超出上界 2.7%，离停下报告的线（900 万）还远。没有重跑。
4. **会话把自己的日志放进了驱动的目录。** project-next 会话把验证日志写在 `.autoskills/runs/` 下（`t1-verify` 这类名字），和驱动的运行目录挤在一起。名字不撞，驱动和验收包读这个目录时都容得下。这是现用版技能的行为，没有改。

## 没有走到的

这一趟一路顺利，下面这些路没有碰到，仍然只在替身测试里走过：

- 复验没过以后的返工，和返工两轮不过以后的跳过；
- 额度用完以后的等待；
- 会话挂死以后被结束；
- 接着做断在“已自动验证”的任务；
- 停止文件和 Ctrl+C；
- 自动模式自己的分类器拦下命令。
