# 手动并行

给负责人和主控看。一个阶段的活能切成几块互不相干的，就开几个终端窗口同时做，主控在前后收口。规则写在 project-plan（怎么拆）和 project-next（怎么记账、怎么收），这一页讲做法。

## 什么时候用

- 用：一个阶段能切成几块，每块有自己的目录、自己的验证命令，互不改同一批文件；共用的接口和骨架能先定下来。
- 别用：活切不开；几块要改同一批文件；共用接口还没想清楚（窗口会各自改契约）；额度紧。
- 默认串行。只在负责人点名“这个阶段并行”时用。

## 从负责人的角度

| 步 | 负责人做什么 | 主控做什么 |
|---|---|---|
| 1 | 规划时说“这个阶段并行，分 N 块” | 拆成契约任务（共用的接口、类型、目录骨架）、N 个块任务、联调任务 |
| 2 | 确认计划 | 落账；串行做完契约任务；用 `git worktree add` 给每块建目录和分支；写好每块的窗口说明文件并提交；把每块的启动命令打印出来 |
| 3 | 开 N 个终端，每个粘贴一行启动命令 | 块任务标成进行中，备注写“受阻：窗口 <块名> 在做”；做不相干的活，或者停下等 |
| 4 | 窗口都停了，回一句“都做完了” | 逐块看完成标记和改动范围，在那一块的目录里跑它的验证命令 |
| 5 | 看汇报 | 按顺序合并，合并后整体再验一次，记账，做联调任务 |

窗口不碰账本，记账只由主控做。窗口做完的标记是最后一个提交说明末尾的一行 `AutoSkills-Done: <块名>`。

## 窗口说明文件的模板

每块一份，放在仓库里（这一批放在 `docs/windows/finish/`），由契约任务提交，窗口开工前就在它的分支上。

```markdown
# 窗口 <X>：<这一块做什么>（块名 <x>，任务 <id>）

先读 <共用约定那一页>，再读 <设计页的哪几节>。

这个窗口没有账本工具，是有意的，不算出错：不要去设项目目录，不调账本工具，
不用 project-* 技能，不取别的任务。

## 范围
只改：<文件和目录>。别的文件只读。

## 契约在哪
<共用的接口、类型、目录骨架在哪些文件；这些文件不改，觉得不对就停下写明要改什么、为什么>

## 要做的
<交付物和验收标准>

## 自测
<命令，一条一行，全名，不用匹配不到也退出 0 的通配>

## 不做的事
不碰账本，不用 project-* 技能，不合并，不换分支，不 push，不动别的 worktree，不改用户级。

## 做完
自测通过后提交，只 git add 自己范围里的文件。最后一个提交说明末尾加一行
`AutoSkills-Done: <x>`（没有新改动就做空提交）。然后停下，列出提交号、跑过的命令和退出码、没做完或拿不准的地方。

## 卡住
写明卡在哪、试过什么、需要什么，停下等负责人。不为了过测试删断言、跳过用例。
```

## 启动命令

这一批用的是关掉全部 MCP 服务的办法：

```
claude --strict-mcp-config --mcp-config <空配置文件> --model <模型> --effort <档位> "<提示词>"
```

- `<空配置文件>` 是一个只有 `{"mcpServers": {}}` 的 JSON 文件，放在仓库外面（比如主检出里不进 git 的目录）。`--strict-mcp-config` 让会话只用这个文件里的服务，于是一个都不起。
- 在那一块的 worktree 目录里启动。提示词一句话就够，比如“你是手动并行的窗口 T（块名 t）。照 docs/windows/finish/t-text.md 做，先读 docs/windows/finish/README.md。”
- 取多个值的选项（`--mcp-config`、`--add-dir`、`--disallowedTools`）后面不能直接跟提示词，否则提示词会被当成它的又一个值。在它和提示词之间先放一个只取一个值的选项，比如 `--model` 或 `--effort`。
- 钩子照常跑。窗口启动时 SessionStart 钩子仍会提示“先设项目目录”，说明文件里那句“没有账本工具是有意的”就是为这个写的。
- 模型和档位按块的难度给，几个窗口同时在用同一份额度。
- Codex 窗口：要用另一个参数关账本工具（`-c mcp_servers.project-manager.enabled=false`），目录同样用 `git worktree add` 建好的。**未试**：没有在真实的 Codex 会话里验证过。

## 几种意外

- **窗口中断**：它是完整的会话，在那个目录里 `claude --continue` 接着做；没提交的改动还在。
- **某块没做完，想先合别的**：照常收做完的那几块；没做完的块任务保持进行中，备注改成实际的情况，联调任务等它。
- **合并冲突**：说明文件分好了范围，正常不会有。有的话，纯机械的主控直接解，别的并进联调任务。
- **额度不够**：几个窗口同时用额度，比串行更容易撞上限，这一点解决不了。撞上了就让窗口停在能恢复的点（提交过的改动不会丢），之后 `claude --continue`；或者少开几个窗口、降档位，剩下的块串行做。

## 例子

AutoSkills 3.0 收尾这一批（AS3-364 到 AS3-372）就是照这个做法做的：契约任务 AS3-364，三个块任务 AS3-365 到 AS3-367，主控收窗口是 AS3-368。共用约定和三份说明文件在 `docs/windows/finish/`，实测情况在同一目录的 `result.md`（主控收完以后写）。
