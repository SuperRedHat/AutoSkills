# 在会话里起长跑驱动：部署前的一次真实探查（AS3-373）

2026-11-20，在一次性测试仓库上做。看三件事：会话起的驱动能不能活过起它的会话；照新文字做的会话会不会把事情做对；驱动还在跑的时候，另一个说“继续”的会话是不是只读。

## 结论

- 一个真实会话听到“起长跑，只做 2 个任务，模型用 claude-opus-5-5，档位 high”，照新文字在新窗口里起了驱动，选项是 `--max-tasks 2 --model claude-opus-5-5 --effort high`。它起之前在账本里记了一条，起之后没有再写账本。
- 起它的会话结束以后，驱动接着跑，做完 2 个任务后以“到了 --max-tasks”停下，退出码 0。两个任务的复验都通过。
- 驱动还在跑的时候，第二个真实会话说“继续”：它查到锁，查到锁里的进程还活着，只读汇报，没有写账本，没有改文件。
- 账本文件的 14 次变化都落在某个会话之内。落在第二个会话那段时间里的 2 次，是驱动的会话把 T1 改成进行中。
- 自动模式没有拦起窗口的那条命令，三个会话的权限拒绝都是 0 次。
- 用掉 224 万 token，按命令行报的美元是 1.89 美元。

## 第 1 步的会话做了什么

1. 读了新文字的两个文件（project-next 的“长跑”一节和 `long-run.md`）。
2. 设项目目录，看了 `git status`（干净）、项目契约和账本里的任务（有就绪的），确认没有驱动在跑。
3. 跑了那段找脚本的 PowerShell，找到主检出的 `scripts/autoskills.mjs`。
4. 用 `add_log` 记了一条：要起长跑、选项、当时的时间。这是它唯一一次写账本，比驱动开始早 7.7 秒。
5. 用 `Start-Process` 起了新窗口。
6. 等 5 秒读锁，查到锁里的进程是 node，还活着。
7. 告诉用户运行名、选项、报告的位置、怎么停、不要直接关窗口，然后结束。

文字没有要求、它多做的两件事（都只读）：把主检出的脚本和分支上的比了一下；跑了一次 `help run`。

## 第 2 步的会话做了什么

1. 读了新版 project-resume。
2. 和读 git 的命令一起看了锁文件，再用 `Get-Process` 查锁里的进程：活着，是 node。
3. 调了三个账本工具，都是读：设项目目录、读服务信息、读项目上下文。没有调写账本的工具，没有用写文件的工具。
4. 告诉用户长跑在跑（运行名、开始时间），给了三种做法：等它跑完、让它停、只看进度。

## 没有探到的

- **自然触发。** 只说一句“起长跑”、不指文件时，部署后的技能会不会被用上，这次探不了，放在 AS3-375。
- **驱动自己起的会话读到新文字会怎样。** 这次驱动的两个会话读的是用户级的旧技能。新文字给它们留的例外，是按提示词里“这是无人值守的运行”这句话认的；测试只钉住了这句话在两边的字面一致，没有真实会话验过。放在 AS3-375。
- **开着窗口的交互式会话。** 这次的会话都是无头的。
- **驱动停了以后说“继续”。** 新版 project-resume 这时要读一遍驱动的报告，并记一条日志。没有跑：会话会接着把剩下的 5 个任务做完。
- **“停下长跑”。** 主控替负责人跑 `stop` 这一句没有跑。`stop` 命令自己有测试。
- **直接关掉驱动的窗口会怎样。** 没有试。
- **一个环境因素。** 测试仓库在 AutoSkills 仓库里面，会话读得到 AutoSkills 自己的契约，其中有一句“长跑驱动在本仓库上跑着的时候，别的会话不记账”。第 2 步的会话确实照新文字查了锁，但不能排除这句话也起了作用。负责人别的项目里没有这句话。
