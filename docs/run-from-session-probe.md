# 在会话里起长跑驱动：部署前的两次真实探查（AS3-373）

2026-11-20，在一次性测试仓库上做。看三件事：会话起的驱动能不能活过起它的会话；照新文字做的会话会不会把事情做对；驱动还在跑的时候，另一个说“继续”的会话是不是只读。

做了两次。第一次用的是第一版文字。独立校验之后文字改了几处（见“两次之间改了什么”），所以用改后的文字又做了一次小的。现在仓库里的文字就是第二次用的。

## 结论

两次的结果一样：

- 一个真实会话听到“起长跑，只做 N 个任务，模型用 claude-opus-5-5，档位 high”，照新文字在新窗口里起了驱动，选项是 `--max-tasks N --model claude-opus-5-5 --effort high`。它起之前在账本里记了一条，起之后没有再写账本。
- 起它的会话结束以后，驱动接着跑，做完 N 个任务后以“到了 --max-tasks”停下，退出码 0。每个任务的复验都通过。
- 驱动还在跑的时候，第二个真实会话说“继续”：它查到锁，核对出驱动还活着，只读汇报，没有写账本，没有改文件。
- 账本文件的每一次变化都落在某个会话之内（第一次 14 次，第二次 7 次）。落在第二个会话那段时间里的，是驱动的会话在改任务状态。
- 自动模式没有拦起窗口的那条命令，所有会话的权限拒绝都是 0 次。
- 两次一共用掉 374 万 token，按命令行报的美元是 3.20 美元。

## 起驱动的会话做了什么

两次的顺序一样：

1. 读了新文字的两个文件（project-next 的“长跑”一节和 `long-run.md`）。
2. 设项目目录，看了 `git status`（干净）、项目契约和账本里的任务（有就绪的），确认没有驱动在跑。
3. 跑了那段找脚本的 PowerShell，找到主检出的 `scripts/autoskills.mjs`。
4. 用 `add_log` 记了一条：要起长跑、选项、当时的时间。这是它唯一一次写账本，比驱动开始早 7 秒多（第一次 7.7 秒，第二次 7.3 秒）。
5. 用 `Start-Process` 起了新窗口。
6. 核对锁。第一次是等 5 秒读锁，再查进程；第二次用的是现在页面上那两段：等锁出现，再核对，结果是 `driver alive True`。
7. 告诉用户运行名、选项、报告的位置、怎么停、不要直接关窗口，然后结束。

文字没有要求、它多做的事（都只读）：把主检出的脚本和分支上的比了一下；跑了一次 `help run`。

## 说“继续”的会话做了什么

1. 读了新版 project-resume。
2. 和读 git 的命令一起看了锁文件。第二次接着读了 `long-run.md`，跑了核对的那一段，结果是 `driver alive True`；第一次是自己用 `Get-Process` 查的。
3. 调的账本工具都是读（设项目目录、读项目上下文；第一次还读了服务信息）。没有调写账本的工具，没有用写文件的工具。
4. 告诉用户长跑在跑（运行名、开始时间），以及等它跑完、让它停、只看进度这几种做法。

## 两次之间改了什么

独立校验第 1 轮没有发现行为上的问题，提了 8 条小问题，都改了：

- 等锁：从“等 5 秒读一次”改成最多等 20 秒。
- 查锁：改成一段 PowerShell 直接给出结论。进程要活着、是 node、启动得不比锁里记的开始时间晚，才算驱动；原来不比启动时间，进程号被别的进程用上时会判错。没有锁文件时说 `no lock`，不再报错。
- 读设置文件和钩子配置时按 UTF-8 读。原来不指定，文件里有中文时 Windows PowerShell 5.1 会读坏。
- project-resume：没有锁文件就不用去读那一页。读驱动报告的条件，从“账本日志里没提过”改成“报告比账本最后一条日志新”。运行目录里没有报告的，按驱动被强行结束处理。
- 另外三句：驱动在主检出当前的分支上干活；路径里有单引号要写两遍；起过长跑的会话动手之前先核对驱动停了没有。

project-next 的 `SKILL.md` 两次之间没有改。

## 没有探到的

- **自然触发。** 只说一句“起长跑”、不指文件时，部署后的技能会不会被用上，这两次探不了，放在 AS3-375。
- **驱动自己起的会话读到新文字会怎样。** 两次里驱动的会话读的都是用户级的旧技能。新文字给它们留的例外，是按提示词里“这是无人值守的运行”这句话认的；测试只钉住了这句话在两边的字面一致，没有真实会话验过。放在 AS3-375。
- **开着窗口的交互式会话。** 这两次的会话都是无头的。
- **驱动停了以后说“继续”。** 新版 project-resume 这时要读一遍驱动的报告，并记一条日志。没有跑：会话会接着把剩下的任务做完。
- **锁的几种少见情况。** 锁留下了而驱动已经不在、进程号被别的进程用上，这些只在测试里用替身进程验过，没有真实会话碰到。
- **“停下长跑”。** 主控替负责人跑 `stop` 这一句没有跑。`stop` 命令自己有测试。
- **直接关掉驱动的窗口会怎样。** 没有试。
- **一个环境因素。** 测试仓库在 AutoSkills 仓库里面，会话读得到 AutoSkills 自己的契约，其中有一句“长跑驱动在本仓库上跑着的时候，别的会话不记账”。说“继续”的会话确实照新文字查了锁，但不能排除这句话也起了作用。负责人别的项目里没有这句话。
