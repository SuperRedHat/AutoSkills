# ADR-009：AutoSkills 3.0 收尾 —— 长跑驱动、验收包、手动并行

- **状态**：Accepted —— 收尾的设计页于 2026-11-19 获负责人确认；任务 AS3-364..AS3-372。实现、独立审查和真实试跑的结果见 §5。部署和完工验收由负责人做（AS3-371、AS3-372）。
- **日期**：2026-11-19
- **作者**：Claude Code（主控是 Fable 5.2；三个手动窗口是 Opus 5.5、Sonnet 5.5、Opus 5.5）
- **目标组件**：`scripts/autoskills.mjs` 和 `scripts/lib/`（两条命令和它们共用的两个模块）；四个技能和审查员定义的文字；`docs/`。**不改** `mcp/project-manager`（仍是 1.5.1）、钩子、部署脚本和契约模板。
- **依据**：收尾的设计页和账本里的 PRD（完工标准 5 条）。设计页留在仓库外的本地私有目录，本 ADR 把用到的内容写全，不需要另读。

## 1. 背景

第 1 批（ADR-006）之后，负责人的时间主要花在三处：隔一阵回来说一句“继续”；等验收的任务越积越多，没有一处能一眼看全；一个阶段里互不相干的几块只能排队做。

原计划的第二步想用程序解决这些：账本换成数据库，每个任务由独立的执行程序取证，再在上面做自动并行。它做到试点为止：过了第一道门禁，第二道没有过，试点里并行比串行慢。2026-11-19 负责人定了方向：先把项目做完，在现用版上加三样轻的东西，第二步存档。

所以这一批的取舍是：不换账本，不加新的强制层，新加的东西都是仓库里的脚本或几行文字，出了问题删掉就回到第 1 批的状态。

## 2. 决定

### 2.1 终点和范围（F1）

- 完工标准换成 5 条：一条命令能在测试仓库上无人值守做完一串任务并复验、有报告；待验收的任务能出一页验收包；手动并行走通一次；部署到用户级、检查脚本通过；文档和 PRD 收口、旧分支存档。
- 3.0 原来的最终效果 8 条原文保留，逐条记下收尾时的状态，没达到的记成搁置，不作废（见 PRD）。
- 账本仍是 1.5.1，不迁移。

### 2.2 一个入口，三条命令（F2）

- `node scripts/autoskills.mjs run <项目目录>`、`stop <项目目录>`、`accept <项目目录>`。入口只负责找命令，每条命令是一个 `(参数, 输出) => 退出码` 的函数。
- 退出码三条命令统一：0 做完，1 失败，2 用法错误。
- 命令不部署：从仓库直接跑。技能文字里不写命令的路径，只写它们在项目里留下的文件。

### 2.3 只读账本（F3）

- `scripts/lib/ledger-read.mjs` 直接读项目的状态文件，从不写。就绪规则、读取时补的默认值、哪些任务要人工验收，都照服务端的写法；有一条不是服务端的：项目契约写了“待验收不挡下游”时可以按它读。
- 备注里有“受阻：”的任务算受阻，这是 project-next 记受阻的办法。
- 账本同一时间只能有一个写入方。驱动跑着的时候，写账本的是它起的会话里的服务端进程；负责人自己的会话这时不要在同一个项目里记账。

### 2.4 两条命令只通过文件碰面（F4）

`scripts/lib/run-paths.mjs` 定下项目里 `.autoskills/` 下每个文件的位置和格式：锁文件、停止文件、项目设置、每次运行的目录、驱动复验的结果、验收包。驱动写，验收包读，互不调用对方的代码（只有驱动结束时经入口调一次 `accept`）。

### 2.5 驱动：一个任务一个新会话（F5）

- 挑任务：先接手上的活（进行中的；以及上一个会话断在“已自动验证”、还没记成完成或待验收的），受阻的跳过；没有就按服务端的规则取下一个就绪任务。一个能做的都没有就不起会话，停下并写明原因。
- 起会话：`claude -p <提示词>`，工作目录是项目根目录，清掉上一层会话带来的环境变量，把账本的项目目录钉在这个项目上。提示词是“用 project-next 只做 <任务号>；做完、验证、提交、记账就结束；这是无人值守的运行，不要提问，要我定的事写进任务备注和汇报”。
- 会话怎么起、怎么读用量、怎么认额度用完、怎么结束挂死的进程，改自评测用的会话驱动。搬进仓库的每个文件都用带私有词表的 privacy 检查查过。
- 断在“已自动验证”的任务原先没人接：它既不是就绪也不是进行中，驱动会报“只剩负责人的事”。这是主控在审查后的修复里发现并补上的，提示词让会话照 project-resume 的规矩接。

### 2.6 复验（F6）

- 任务到了完成或待验收，驱动先看工作目录干不干净（账本目录和 `.autoskills/` 不算），再把任务的验证命令逐条重跑，每条一个进程、有超时，输出留在这次运行的目录里。
- 用哪个 shell 由项目设置定，默认 Windows PowerShell 5.1，可以改成 Git for Windows 的 bash。
- 结果三种：通过；没过（有命令没过，或者工作目录不干净所以没跑）；没有跑（任务没有验证命令）。
- 复验在原地跑。它查得出“忘了提交”，查不出“靠本机才有的东西才过”。

### 2.7 复验没过（F7）

- 任务已经是完成：驱动不改它的状态，下一个会话的提示词让它照 project-plan 的做法新建一个返工任务并只做它。修两轮还不过，让会话在返工任务的备注里写“受阻：”，之后跳过。返工收尾之前，别的任务不抢在前面。
- 任务在待验收：不动它，报告和验收包里标出“复验没过，建议驳回”。驳不驳回由负责人定。

### 2.8 刹车（F8）

| 管什么 | 做法 | 默认 |
|---|---|---|
| token | 不设上限，每做完一个任务报已用多少、按平均还要多少 | — |
| 时间 | `--until HH:MM` 以后不再开新任务 | 关 |
| 任务数 | `--max-tasks N` | 关 |
| 没进展 | 连续 3 个会话既没有新提交、任务状态也没变，就停 | 开 |
| 反复不过 | 返工两轮还不过，跳过 | 开 |
| 会话挂死 | 30 分钟没有任何输出才结束这个会话和它起的进程 | 开 |
| 额度用完 | 等 10、20、40 分钟，之后每次 60 分钟，再接着做同一个任务 | 开 |

任何一条都不打断正在做的任务。做完的任务已经提交、记账，所以停下不丢东西。

### 2.9 停法和锁（F9）

- 稳妥的停法是停止文件（`stop` 命令写它）：驱动做完手上的任务后停。
- Ctrl+C 按一次等同停止文件。会话在自己的隐藏控制台里跑，收不到驱动窗口里的 Ctrl+C，这是用替身程序探出来的。按两次立即停：当前会话连同它起的进程一起结束，改了一半的留在工作目录里，退出码 1。
- 一个项目一个驱动。锁文件用独占创建；活着的驱动的锁谁也不动；接手死掉的驱动留下的锁，一次只让一个驱动做，并且只删它读到过的那把。测试里六个进程同时抢，恰好一个拿到。
- 退出码：0 是正常的停点（全部做完、只剩负责人的事、停止文件或一次 Ctrl+C、到了限额）；1 是刹车、第二次 Ctrl+C 或出错。“剩下的都受阻”算 1：它要人来看。

### 2.10 权限模式（F10）

- 默认自动模式（`--permission-mode auto`）。依据是探查：自动模式下无头会话把一个任务做完了；被守卫钩子或拒绝规则拦下的命令作为错误回到会话里，会话照常收场，不会卡着等人点。
- 换成跳过权限检查的模式时，守卫钩子和拒绝规则仍然生效，也探过。但默认不用它，要用得负责人自己在命令行上写。
- 没探到的：自动模式自己的分类器拦下命令时会话怎么收场。

### 2.11 验收包（F11）

- 读账本和驱动的复验结果，写一页 HTML 到项目的 `.autoskills/acceptance/`，打印路径。不起会话，不写账本。
- 页面按模块分组；门禁任务在前，其次是通过后能放开更多任务的，再按账本先后。每个任务列出验收标准、检查清单、备注原文、通过后能放开的任务、驱动复验的结果。页首给出点名任务的回复例子。有长跑在跑时，页首给出可以直接粘贴的停止命令。
- 页面是一个自包含的文件，不引用外部资源，任务里的文字一律转义。
- 只有驱动判了没过的任务才标“建议驳回”，并写原因。任务没有验证命令时写“没有跑”，不建议驳回：人工验收的任务常常没有验证命令，这一条原先显示错了，是独立审查查出来的。
- `--out` 不能指进项目的账本目录，按真实路径判断。

### 2.12 套件文字（F12）

要部署的只有这些文字。技能正文相对第 1 批净增 12 行（加 15 行、减 3 行），上限是 40 行。

- project-status：项目里有当天的验收包就给出路径。
- project-feedback：项目里有长跑在跑时，先请用户停下它再记账；删掉一句已经不会发生的话。
- project-plan：三条规划规则。粒度（默认串行，一个任务是一个模块或目录级的交付，高风险的小改动单独成任务）；本人验收点（同一阶段要用户看的东西合成一个验收任务放在阶段边界，不减少要用户看的东西）；并行（只在用户点名时用，拆成契约任务、几个块任务、联调任务）。
- project-next：手动并行怎么记账、怎么收；独立校验一步里对应 §2.13 的一句；停点 2 加上“块任务在等用户开的窗口做完”。
- project-verifier 的定义：§2.13 的一句。
- `docs/manual-parallel.md`：一页做法和窗口说明文件的模板。

### 2.13 审查员的例外（F13）

这是放宽检查，单独记。

- 起因：审查员定义写着“找不到证据的条目就是没满足”，门禁任务又要先过审查。验收标准里要是有一条“负责人本人确认”，审查员找不到证据，任务就卡住，而负责人的确认要等任务到了待验收才会有。
- 负责人 2026-11-19 同意的原句：只有负责人本人能确认的条目留给本人验收，不因为缺他的确认判失败；其余条目照旧审。
- 最终的写法比原句窄：只有任务做完会停下等用户验收时（`acceptance_mode` 是 manual，或是 milestone_manual 且 `stage_gate=true`），这类条目才留给本人验收；任务做完不会停下的，照样判没满足，并写明这一条没有人验收。条目里能用文件、diff 和日志核对的部分照旧核对；其余条目找不到证据的，一律判没满足。
- 为什么收窄：独立审查指出，原句没有要求留下的条目之后真的有人验收。自动完成的任务里要是写了这类条目，审查员会放行，之后没人验收，无人值守时更不容易发现。收窄以后这种任务照旧判没满足，规划上的错会露出来。
- 收窄是主控定的，不是负责人定的。例外成立的情形是原句的子集；三次独立审查的结论都是“只窄不宽，不算削弱”。部署前讲给负责人，他要原句就改回去。

### 2.14 手动并行（F14）

- 只有文字，没有脚本。规划时拆成契约任务（共用的接口和骨架，串行先做）、几个块任务（各自的目录、验证命令和说明文件，互不改同一批文件）、联调任务。
- 窗口不碰账本。这一批用的办法是启动时关掉全部 MCP 服务（`--strict-mcp-config` 加一个空的 `--mcp-config`），不是设计页先写的 `--disallowedTools`：前一种写法以前用过，后一种的通配写法没试过。
- 块任务在窗口干活期间是进行中，备注写“受阻：窗口 <块名> 在做”，循环会跳过它。窗口做完的标记是最后一个提交说明末尾的一行。
- 主控收：逐块看完成标记和改动范围，在那一块的目录里跑它的验证命令，按顺序合并，合并后整体再验，记账。
- 完成信号在文字里是负责人回一句“都做完了”。这一批负责人在窗口还在干活时就把目标交给了主控，主控用后台循环等完成标记。

### 2.15 验证从轻（F15）

负责人 2026-11-19 定：单元测试、一次真实试跑、驱动、验收包、套件文字各一次独立审查。不做变异测试、证据清单和门禁程序。实际做的比这多一点：验收包的独立审查没过，修完按规矩复核了一轮；最后改动的两处又定向审了一次。

## 3. 不做的

- 自动并行、账本 2.0、按任务取证的执行程序的任何后续；账本迁移。
- Codex 上的长跑驱动；按任务大小自动选模型（只留 `--model`、`--effort` 两个参数）。
- 把命令部署到用户级；建窗口的脚本；合并脚本；后台等完成信号的程序。
- 守卫钩子里拦“长跑期间别的会话写账本”的规则：先用技能里的一句话，出过一次再建。
- 用 AI 给待验收的任务写摘要；技能正文长度的 lint；账本 1.5.1 的小修。
- 审查员建议、这一批没有采纳的一处：project-next 把任务列给用户验收时，不单独点出审查员留给本人的那几条。它超出了设计页定的六处改动；验收包会列出全部验收标准。

## 4. 后果与残余风险

- **驱动跑着的时候，同一个项目里别的会话不能记账。** 服务端没有锁，两个进程同时写会丢更新。现在只靠技能里的一句话和验收包页首的提示。
- **原生 Windows 上没有沙箱。** 无头会话在自动模式下跑，守卫钩子和拒绝规则照常生效，但护栏只防误操作，不防有意绕过，这一点和第 1 批一样。
- **只在替身测试里走过、真实会话里没碰到的路**：复验没过以后的返工、返工两轮不过、接着做断在“已自动验证”的任务、额度用完以后的等待、会话挂死、自动模式的分类器拦下命令。
- **锁有两种极端顺序不保证**：一个驱动写锁文件时中途停了四分之一秒以上；接手旧锁时删锁和建锁之间被别的驱动抢先（这时报告里少一句“接手了旧锁”）。不要用脚本同时起几个驱动。
- **复验用 PowerShell 跑时，失败的命令退出码一律记成 1**，不是命令自己的退出码。
- **会话和驱动共用 `.autoskills/runs/` 目录。** project-next 会话会把自己的验证日志放在这里，名字不和驱动的运行目录撞，读这个目录的程序都容得下。
- **每个任务新开会话有固定开销**：技能、契约、账本工具的说明每次都要付一遍。试跑里每个任务的数见 §5。
- **Codex 上只有技能文字**，没有长跑驱动；Codex 窗口的手动并行没试过。
- **放宽的那一句比负责人确认的原句窄**，见 §2.13。

## 5. 验证和结果

### 5.1 独立审查（AS3-370）

每次都用只读的独立校验者（Opus 5.5、high），只给原始标准、diff 和主控跑的验证日志，不给实现方的总结。

| 轮 | 驱动 | 验收包 | 套件文字 |
|---|---|---|---|
| 第 1 轮 | 通过，minor 7 | **不通过**，major 1、minor 4 | 通过，minor 5 |
| 第 2 轮（修完复核） | 通过，minor 3 | 通过，minor 3 | 通过，minor 4 |
| 定向审查（最后改的两处） | 重写的锁：通过，minor 3 | — | 例外那一句的最终写法：通过，minor 2 |

- blocker 一直是 0。major 只有一条：任务没有验证命令时，验收包把驱动的“没有跑”显示成“没过，建议驳回”。修了，复核判“解决了”。
- minor 里便宜的都修了。留下没修的写在 §3 和 §4。
- 例外那一句审了三次：负责人确认的原句、收窄的第一版、最终写法。三次的结论都是没有超出负责人同意放开的那一类。
- 定向审查之后还改了两行（锁在接手时只删它读到过的那把），没有再送审；依据是并发抢锁的测试连跑 20 遍都是恰好一个拿到。
- 验收包在第 2 轮之后还改过两次，都没有再送审：第 2 轮三条 minor 的修复（`--out` 按真实路径判断、被中途结束的命令照实写、用法页列全五种写法），和试跑查出的那处缺陷的修复（§5.2）。两次都带测试，依据是验收包的测试文件全过。

### 5.2 真实试跑（AS3-369）

在 7 个任务的测试仓库上跑了一整趟，Claude Code 2.1.328，Opus 5.5、high，自动模式。详见 [finish-trial.md](finish-trial.md)。

- 一条命令一趟做完 7 个任务：6 个完成，验收点 T6 停在待验收；驱动以“只剩等负责人验收”停下，退出码 0。
- 驱动的复验 7 个都通过。隐藏测试 7/7。
- 驱动没有写过账本：试跑期间账本文件的 49 次变化，没有一次落在会话之外。
- 7 个任务 579 万 token、14 分钟；加上验收那一个会话共 616 万。
- **每个任务新开会话并不更省。** 2026-11-01 现用版一个长会话做完是 548 万，这次多 6%，算上验收多 12%。token 的九成以上是每次请求都要带的固定内容，任务小的时候新会话省不回来。设计页里“更省”那条假设在这个小仓库上不成立；任务大的时候怎样没有量。
- 要人回来的次数和现用版一样，都是验收那 1 次。
- 试跑查出一处缺陷：驱动收尾时自己出的验收包，页首写着“有长跑正在跑”。修了，并重跑了受影响的那一段。

### 5.3 手动并行的实测（AS3-368）

这一批自己就是用三个手动窗口做的，算完工标准第 3 条的实测。详见 [windows/finish/result.md](windows/finish/result.md)。

- 三个窗口同时开工，分别用了 26.5、1.3、2.8 分钟。三次合并都没有冲突，合并后 13 个测试文件和 lint 全过。
- 窗口没有碰账本：账本文件的哈希前后相同，会话记录里没有账本工具的调用。关掉全部 MCP 服务的办法管用。
- 启动钩子仍然提示“先设项目目录”，没有一个窗口因此停下：窗口说明里那句“没有账本工具是有意的”起了作用。
- 两样东西只在主检出（部署测试要用的恢复工具、私有词表），在 worktree 里做整体再验时要另外处理。

### 5.4 和设计页不一样的地方

| 设计页 | 实际 | 原因 |
|---|---|---|
| 窗口用 `--disallowedTools` 关账本工具 | 关掉全部 MCP 服务 | 前一种的通配写法没试过，后一种以前用过 |
| 审查员的例外照原句 | 收窄成只对会停下等验收的任务成立（§2.13） | 独立审查指出原句下自动完成的任务里这类条目没人验收 |
| 手动并行的完成信号是负责人回一句话 | 这一批主控用后台循环等完成标记；文字里仍是回一句话 | 负责人在窗口还在干活时就把目标交给了主控 |
| 驱动先挑进行中的任务 | 还会接断在“已自动验证”的任务 | 不接的话这种任务没人做，驱动会误报只剩负责人的事 |
| 按任务开新会话更省 token（设计页标了“没实测”） | 在测试仓库上多 6% 到 12% | 见 §5.2 |
| 手动并行另做一个两窗口的小样 | 没有另做 | PRD 定的是这一批本身用三个窗口做，算这一条的实测 |

### 5.5 部署

要部署的只有四个技能和审查员定义的文字：Claude Code 一侧 5 个文件，Codex 一侧 4 个（它没有审查员定义这个文件），共 9 个目标。部署由负责人在主检出的普通终端里做，步骤和回滚见 [deploy.md](deploy.md)。部署 id 和部署后的检查结果记在账本 AS3-371 的备注里；这个任务自己的独立校验（文档、合并、部署的范围）的结论记在同一个任务的备注和日志里。

## 6. 备选方案

- **接着做第二步。** 没选：试点里并行比串行慢，第二道门禁没过，再做下去的投入和这三样轻的东西不在一个量级。
- **换一个现成的工作流层。** 没选：外部调研看过，换了要重学一套，账本和技能都得跟着改。
- **驱动自己改任务状态、自己建返工任务。** 没选：账本同一时间只能有一个写入方；状态怎么走是技能的规矩，驱动再写一份就有两份规则。
- **驱动里设 token 预算。** 没选：负责人的顾虑是预算会打断做到一半的任务。改成只报告用量，限额只管开不开下一个任务。
- **审查员的例外照原句不收窄。** 没选，原因见 §2.13；负责人可以要回原句。
